# 平台管理页 - 用户管理、模块管理与展示屏幕

这三页的管理功能只对超级管理员及以上开放；站长另有审计日志与服务器管理，见 [server.md](server.md)。

## 用户管理

侧栏「用户管理」。内容区一张账号表：列是 用户名 / 称呼 / 角色 / 状态 / 最近登录 / 操作；
表头右侧是搜索框，列表底部 [加载更多]。

每行的操作列可以改角色、封禁或停用、重置密码、[调整存档配额]（助手对话的存档上限）。
待审核的账号不在这里批，在「活跃审批 › 注册申请」。

### 彻底删除账号

账号详情弹窗里有 [彻底删除]，超管及以上、要进 sudo，删掉就找不回来。它**不会**无条件出现：
四个条件都满足才有这颗按钮，否则弹窗里会写出还差什么。

- 账号是**已停用**状态，而且停用满 `delete_account_after_days` 天（静态设置，默认 3 天）
- 名下没有还在用的活动——先转移负责人再删人
- 名下没有名单与报名——那是别人也要用的长期资产
- 站长自己的账号不能删

删除时一并收掉：会话、API 令牌、助手存档、头像、活动席位、站内通知、草稿、预设收藏。
**审计不删**：它记的是账号编号，删完那几行显示成 `账号 #10003`，历史与身份还认得出。

已归档的活动不拦着删人：删掉之后那场活动的负责人一栏显示「账号已删除」，取消归档时
需要同时指定新的负责人（见 [活动](events.md)）。

## 活动管理

侧栏「活动管理」，超级管理员及以上。

内容区两张表：**当前活动**与**归档的活动**，两张表的列与宽度一致：活动 / 活动号 / 负责人 /
时间（当前活动是创建时间，归档的是归档时间）/ token / 操作。活动名旁边如果挂着红色的
「不可用」胶囊，说明它依赖的模块被停用了（悬停或点一下能看到原因）。
**首列的活动名可以点开**，详情弹窗里是这场活动的高权限操作：

| 动作 | 当前活动 | 已归档 |
| --- | --- | --- |
| 打开活动设置 ↗ | ✓ | — |
| 下载数据 / 下载完整数据 | ✓ | ✓（含归档包） |
| 转移负责人 | ✓ | — |
| 回收站内资源 | ✓ | — |
| 强制归档 | ✓ | — |
| 取消归档 | — | ✓ |
| 彻底删除 | — | ✓ |

除了「打开活动设置 ↗」「转移负责人」（负责人自己做时不需要提权），其余都要进 sudo；
「彻底删除」不可逆。这一页只管高权限动作，不放新建活动一类的常规入口。

**取消归档时负责人账号可能已经不在了**（账号可以被彻底删除，已归档的活动不拦着删人）：
这种活动在负责人一栏写「账号已删除」，点 [取消归档] 会先让你选一个新的负责人，
确认之后转移与恢复一起完成。

## 模块管理

侧栏「模块管理」。内容区一张表：模块 / 版本 / 作者 / 引用计数 / 操作，最右一列是 [停用] 或 [启用]。
「引用计数」是还在用这个模块的活动数。

停用与启用都是**站级动作**：要先进 sudo（输一次密码），并记审计。

- 停用之后，使用这个模块的活动立刻不可用：已经打开的活动页会自己换成一张说明页，
  说明页写着「此活动不可用 / 此活动必需的资源已被管理员停用」；活动接口返回 503。
  「我的活动」的卡片在标题右边多一枚红色「不可用」胶囊，悬停或点一下能看到原因
- 活动数据一条不动。停用的模块也不再出现在创建活动的列表里，它的预设一并标为不可用
- 启用之后这些活动立刻恢复，刷新页面即可；不用重建、不用改配置
- 装新模块是把目录放进 `modules/`，重启后出现在这张表里

## 展示屏幕

侧栏「外部资源 › 展示屏幕」。页面右上角 [导入]；内容区三块：可用的屏幕、导入说明、引用方式。

- 「可用的屏幕」列出内置与导入的展示屏幕，各自有标识与体积
- 「导入说明」写着导入要求：包内要有 `screen.html`，只收样式表、脚本与图片，压缩包 2 MB 以内、
  解开后 8 MB 以内
- 活动用哪一份屏幕，在活动后台的「活动设置」里选
