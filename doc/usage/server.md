# 服务器与审计 - 机器占用与操作留痕

这两页只有站长能看到。

## 页面结构

- **服务器管理**：页面右上角 [刷新]；内容区「CPU 占用」「内存占用」「运行时长」
  「用户（在线 / 注册）」「服务信息」「安全模式」几张卡片

## 服务器管理

机器占用、运行时长、用户（在线 / 注册）与版本号都在这一页。顶栏左侧的 CPU 与 MEM 也是它的缩写版。
「服务信息」里有一行「安全模式」，写着现在是「是」还是「否」。

### 安全模式

出配置或数据问题时把服务收起来：活动页显示维护提示，数据原样不动，面板照常可用。

进入：内容区「安全模式」卡片里的 [进入安全模式]，确认后服务重启一次，期间活动页打不开。
退出：同一个位置变成 [退出安全模式]，确认后服务重启一次，活动页恢复开放。

这两个动作要重新输入一次密码。重启期间这一页会自己等它回来，回来后自动刷新。

页面上的安全模式开关需要服务由 `bin/service.sh` 启动才生效：那种情况下服务跑在它起的
看护进程里，改完开关能自己重启。服务是手工起的（直接跑 `bin/run.sh`）时，卡片底下会写着
「服务管理未运行，无法自动重启。详见服务文档」，这时只改配置，重启要到服务器上做，见
[部署与运维](../ops/deploy.md)。

备份与日志不在这一页：每个活动自己那一页有「下载数据」，服务器上的日志用
`bin/service.sh log` 看，见 [../ops/deploy.md](../ops/deploy.md)。

## 审计日志

记每一次写入：谁、什么时候、对哪个对象、改了什么。表中一列一件事，翻到底点「加载更多」。
搜索在服务端完成，所以搜的是全部记录，不只是已经翻出来的这些。

审计日志只记改动，不记查看。同一个人带着 API 令牌操作时，操作人仍记本人，
说明后面标着用的是什么令牌。

## 活动自己的日志

每个活动后台还有一份自己的操作日志，只记这场活动里的事，给现场复盘用。两者分开：
面板的审计日志是整台机器的账。
