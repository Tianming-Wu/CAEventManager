# 活动页面与现场 - 地址、大屏、签到与日志

活动的内容是**模块**：装上并启用某个模块，才有它的页面与设置。
平台只提供基础功能和审计框架（活动设置、日志）模块自身要用的界面由模块自己添加。

## 活动后台的页面

顶栏左边是活动名称与「后台」，右边是当前账号和[退出]。

页签由模块与平台拼成，平台始终追加 活动设置 与 日志。模块页签里的内容见模块自己的 doc.md。

这一页没有侧栏：宽度不足 640px 时，顶栏按钮挤在一起、页面左右内边距收窄，页签可以横向滑动。

## 地址

```
/<token>/admin      活动后台（用面板账号登录）
/<token>/login      跳到面板登录，登录后回到这个后台
/s/<短码>            限时短码跳转，由后台生成
```

`<token>` 是 32 位访问凭据，本身就是地址里的一段。数字序号只用于存储，不出现在地址里。
服务挂在子路径下时，前面还会多一段部署前缀——那是服务的地址，与活动无关。

活动后台沿用面板账号与会话，谁能进见 [events.md](events.md)。

## 活动设置

平台画的，管的是与玩法无关的东西：

- **成员**：见 [events.md](events.md)
- **活动信息**：名称、访问地址。重新生成地址后旧链接立即失效，需要重新输一次密码
- **短链**：平台生成的临时跳转地址，模块申请了短链能力才可用，见 [shortlinks.md](shortlinks.md)

## 日志

活动自己的操作日志：谁在什么时候改了什么。不同于平台的审计日志，供现场复盘使用。

发生服务降级时，后台右上角会出现提示。见 [notices.md](notices.md)。

## 模块自己的页面

模块的页面、现场怎么操作、用哪台设备，写在模块自己的说明里：

- 内置的「奖票抽奖」模块：`builtin/modules/nwuca.lottery/doc.md`
- 实例自己装的模块：`modules/<模块 id>/doc.md`

这些说明随应用一起装到机器上，运维助手也能读，所以问「操作台的搜索怎么用」时，
它查到的是模块自己写的那一段。
