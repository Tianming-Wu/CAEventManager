# 抽奖系统（lab812 / xlottery）

社团活动现场抽奖服务。三个页面 + 一个自助签到页，全部无框架、无外部依赖
（Python 3 标准库 + 原生 JS）。

```
/              主面板：登录（根路径直接进登录，页脚有「没有账号？去注册」）
/register      主面板注册（提交后等站长/超管在「活跃审批」里审核）
/login         主面板登录（与根路径同一页）
/panel         主面板控制台（左侧栏导航，见下）

<id>/          某个活动的公示页（扫码打开，只读，无鉴权）
<id>/checkin   签到页（必须扫大屏的时效二维码才能进；签完自动跳公示）
<id>/screen    大屏页（教室投影：二维码 + 实时统计 + 中奖名单 + 抽奖动画）
<id>/admin     该活动的后台操作台
<id>/login     该活动的登录表单
```

`<id>` 是活动 token（32 位 base64url），同时也是该活动后台的访问凭据。主面板在服务根路径，
活动页在 `/<id>/` 之下 —— **加活动不改变任何路径结构**。

**路由与外部前缀无关**：服务先认活动 token（出现在路径任意位置都行），剩下的路径再按主面板
路由匹配，所以本地怎么访问都通，平台前缀换成子域名也不用改代码。`config.json` 的
`public_base_prefix` **只用来生成链接**（二维码、短链、Cookie 路径），不参与路由判定。

主面板的页面用 hash 路由，都挂在 `/panel` 这同一个文档上：

```
#/overview         总览：账号与活动数、我的活动、最近操作
#/events           我的活动（置顶是收到的邀请，下面是自己参与的活动）
#/templates        模板管理                      [计划中]
#/users            用户管理                      [m] 每个账号一个详情弹窗
#/all-events       活动管理                      [m]
#/approval-users   活跃审批 › 注册申请            [m] 待审核 + 最近处理
#/approval-events  活跃审批 › 活动申请            [m] 现在默认自动通过，留位
#/server           服务器管理                    [o] CPU / 内存 / 运行时长
#/audit            审计日志                      [o]
#/account          账户信息（个人资料 / 安全：显示名、登录名、头像、改密码、退出登录）
#/appearance       界面设置（主题：跟随系统 / 浅色 / 深色）
```

`[m]` 只对站长与超级管理员可见，`[o]` 只对站长可见。界面上藏起来只是第一层，
直接改 hash 也会被弹回总览，接口本身就是拒绝的。

侧栏随屏宽改变形态：≥1100px 是完整侧栏，760~1100px 收成图标栏（点分组标题把面板滑出来），
≤760px 变成抽屉（标题栏左上角汉堡按钮）。手指设备上按钮最小 36px、导航项 46px。

发布后（服务名 `xlottery`）：

```
公示 https://lab.nwuca.tech/u/laffey/xlottery/<id>/
签到 https://lab.nwuca.tech/u/laffey/xlottery/<id>/checkin   ← 必须带 ?t= 时效 token
大屏 https://lab.nwuca.tech/u/laffey/xlottery/<id>/screen
后台 https://lab.nwuca.tech/u/laffey/xlottery/<id>/admin
```

不知道 `<id>` 就跑 `./service.sh status`，三个地址直接打出来。

## 2. 大屏的两个阶段

大屏只在两个时段占用：**开场签到** 和 **结尾抽奖**。中间屏幕给别人用。
后台「抽奖」页顶部有阶段开关：

| 阶段 | 大屏显示 |
|---|---|
| **签到** | 居中大二维码（签到码，每 10 秒刷新）+ 已签到人数。仅此两项 |
| **抽奖** | 右上角小二维码（公示页地址）+ 到场/奖票数 + **常驻中奖名单** |

大屏只承担"怎么进场"和"谁中奖"两件事：任务统计、奖票号码都不上屏。
**名字墙**在设置里开关，默认关闭。

签到码是**时效的**：扫到的 token 只在当前 10 秒窗口（外加前一个窗口，容忍网慢）内有效，
所以把二维码截图转发、或者把链接发给没来的人，过期后就签不了。
换阶段不需要重启，后台点一下，大屏 1.5 秒内跟着变。

> 大屏页按 `Q` 可以本地临时切一次大/小二维码，不动服务器阶段（刷新即恢复）。

## 3. 现场流程

### 开场

1. 后台「设置」→ 切到大屏「签到阶段」。
2. 投屏 `/screen`，学生扫码 → 填**学号和姓名**（两个都完全匹配才通过）→ 签到成功页
   显示「第 N 位到场」和自己的奖票号 → 3 秒后自动跳公示页。
3. 没网、学号记不住的，你还可以在「操作台」手动录（搜拼音/学号，`Enter` 记一步）。
4. 后台每 5 秒自动刷新，能看到谁刚签了。

### 中间

同学完成任务后来找你报名字，你在「操作台」记：

- `Enter` = 完成下一个待完成步骤（签到 → 任务一 → 任务二）
- `Shift+1/2/3` = 直接标某一步
- `Ctrl+Shift+Z` = 撤销最后一步（需解锁）
- `Esc` = 清空

> 快捷键刻意避开所有 `Alt` 组合：`Alt+Z` 在装了 NVIDIA App 的机器上是显卡悬浮层。

### 结尾

1. 后台「奖票」页看「速度排名与奖励预览」（**真实会发的结果**）→ 点「结算」。
   结算后池子里的票**全部**发完，一张不留。
2. 后台切成「抽奖阶段」，投屏上台抽奖：「按票抽一张」或「抽特等奖」→ 大屏自动播动画。
3. 中奖名单常驻在大屏上，散场也能看。

## 4. 奖品与抽奖

奖品在 **设置 → 奖品** 里配置，每个奖品有**名称、数量、方式**。数量就是抽取次数，
抽够了按钮自动锁死，不会多抽。

默认按策划案的数量配好（**只放数量，不含具体物品**）：

| 奖品 | 数量 | 方式 |
|---|---|---|
| 特等奖 | 1 | 均等（只在到场者中抽，和票数无关，不消耗奖票） |
| 一等奖 | 2 | 按票 |
| 二等奖 | 5 | 按票 |
| 三等奖 | 10 | 按票 |

「按票」：票越多机会越大，抽中的号码退出后续抽取。
「均等」：每位到场者概率相同，不占用任何奖票。

两种方式互不影响，一个人可以既是某奖项的中奖者又是特等奖得主。
人级抽取默认**不会让同一个人中两次**（设置里可关）。

> **按票抽奖是"票"级的，不是"人"级的**：手里有 3 张票就有 3 次被抽中的机会，
> 所以同一个人可能中多个奖项（尤其是票多的同学）。这是当前规则的自然结果；
> 若要限制"一人只能中一次"需要另加去重规则（目前未启用）。

* **配色**：默认浅色，跟随系统的深色模式（`prefers-color-scheme`）。只有一个强调色

  已做字段语义加固 + 首次输入前自动清除。

## 6. 奖票数量与分配

### 池子（自动模式，默认）

```
奖票池 = 到场人数 × 3 + 额外奖票常数（默认 20）
```

- 跟着**实际签到人数**走，每多签一人自动 +3，报名没来的人不影响
- 数学上永远不会饿死保底票
- 票**全部用完**：结算时「池子 − 保底」全部按速度发出去

也能切**固定模式**（印了确定张数实物票时用）。关键点：

- **涨池子随时可以**，180 → 200 直接改
- **降池子也随时可以**，只要不低于已发张数（只发了 140 张时 180 → 140 是安全的）
- **不需要重置、不需要删数据**：奖票号码是**顺序发号**，和池子大小解耦

### 速度奖励

排序：完成任务数（2>1>0）→ 两个任务内的归一化名次 → 签到时间。
名次 `p` 权重 `w = 1 + β·(M-p)/(M-1)`（首尾 `1+β` 对 `1`，β 默认 1）。
期望票数用**最大余数法**取整，合计严格等于奖励票数；平局用种子哈希（不用名次）。

**常数 C 的实际含义：跑得最快的 C 个人各多拿一张票。** 实测：

| 常数 | 32 人到场 | 49 人到场 | 60 人到场 |
|---|---|---|---|
| 10 | 前 10 人 +1 | 前 10 人 +1 | 前 10 人 +1 |
| **20（默认）** | 前 20 人 +1 | 前 20 人 +1 | 前 20 人 +1 |
| 40 | 8 人 +2、24 人 +1 | 前 40 人 +1 | 前 40 人 +1 |

> `180 = 60×3`，池子定死 180 时全员完成就一张不剩、速度维度直接消失。
> 「预留 200 张」里的那 20 张正好是速度奖励的全部额度。

## 7. 防误操作

后台默认**只能添加**。右上角「解锁修改」打开后才能：撤销、改完成时间、删人、
作废抽奖、重置奖票、取消结算、重新生成访问 id。

打开需二次确认，**30 秒无操作自动上锁**，每次撤销后重新计时。
撤销签到会级联撤销后续任务（弹窗列清影响）。所有动作进操作日志。

> 关于代签：自助签到 + 不核对身份，室友代签是防不住的——时效二维码只挡远程自助。
> 现场有纸质签到作为凭据对照，够用了。

## 8. 名单导入

CSV 或 TSV（Excel 直接粘贴就是 TSV），有表头自动识别，没表头按「学号,姓名」解析：

```csv
学号,姓名,班级
2024001,张三,计科2401
```

* 表头可用 `学号 / 姓名 / 班级 / 拼音 / 首字母`
* **拼音可以不填**：内置 2 万字拼音表自动生成（`张三` → `zhangsan` / `zs`）
* 按学号增量更新，重复导入不产生重复记录，也不删人
* **学号长度不限定**：本科 10 位、研究生 9 位（如 `202622298`）混排也没问题 ——
  系统只把它当字符串精确匹配，不做位数校验

## 11. 已知约束

* **路径前缀**：前端全部相对 URL；服务端先在路径里找 `<id>` 段再路由，两种转发行为都兼容。
* **别手改 `path_secret`**，要换就用后台「重新生成访问 id」（会自动同步 URL 和二维码，
  旧链接和旧二维码立刻失效，奖票数据不受影响）。
* **签到页必须带时效 token**：直接访问 `/checkin` 只会提示"请扫描现场二维码"。
* 时间：数据库存 UTC，页面按浏览器本地时间显示；导出 CSV 用 +08:00。
* 静态资源 120 秒缓存，改完前端 Ctrl+F5。
* Cookie 路径按登录时上报的前缀设置（`/<id>/`）。

```powershell
                                # 主面板页面测试（浏览器，75 项）：登录重试、11 个路由、
                                # 折叠分组、账号弹窗、主题、六种屏宽、触屏可达、
                                # 角色可见性（加 --accounts 才会真实建号）

python tools\prod_check.py https://lab.nwuca.tech/u/laffey/xlottery <id>
                                # 线上只读巡检：路由 + 登录页 + keep-alive（21 项）
.\deploy.ps1                   # 归一化行尾 → 打包 → 上传 → 解包 → 校验文件+import → 重启
```

`deploy.ps1` 会在重启前**逐个校验文件确实落地并且能 import**，缺文件会直接失败而不是
重启进一个坏服务。工具会自动从 `config.json` 读 `<id>` 拼 URL。

`unit_test.py` 是补一个真实的坑：`host_stats()` 里写了 `socket.gethostname()` 却没 import
`socket`，而这行在读 `/proc/stat` 之后才执行 —— Windows 没有 `/proc`，函数提前 return，
本地全绿、线上 500。所以 `/proc` 的根路径做成参数，测试喂一个假的 `/proc` 进去，
Windows 上也能真正跑到那段代码。

**接口测试和页面测试必须都跑。** `panel_test.py` 直接打 `/api/panel/*`，所以两个登录/注册
页面曾经一直把请求发到 `/api/panel/api/login`（页面说“登录”，服务答“未登录”）它都是绿的；
`panel_ui_test.py` 驱动真实页面，才抓得住这类错误。布局同理：只看截图看不出
「表格在手机上横向溢出」或者「图标栏点不到分组子项」，`panel_ui_test.py` 对这六个屏宽
逐个断言横向溢出为 0、外壳高度等于视口，并且在触屏尺寸下真的去点开分组。
