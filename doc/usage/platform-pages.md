# 平台管理页 - 用户管理、模块管理与展示屏幕

这三页的管理功能只对超级管理员及以上开放；站长另有审计日志与服务器管理，见 [server.md](server.md)，
而**模块管理这一页只有站长看得到**（装与停都是整台机器的事）。

## 用户管理

侧栏「用户管理」。内容区一张账号表：列是 用户名 / 称呼 / 角色 / 状态 / 最近登录 / 操作；
表头右侧是搜索框，列表底部 [加载更多]。

每行的操作列可以改角色、封禁或停用、重置密码、[调整存档配额]（助手对话的存档上限）。
待审核的账号不在这里批，在「活跃审批 › 注册申请」。

### 彻底删除账号

它**只对已停用的账号出现**，而且不总是能点：

| 账号状态 | 弹窗里 |
| --- | --- |
| 正常 / 待审核 / 已封禁 | 没有「彻底删除」这颗按钮 |
| 已停用，但停用没满 `delete_account_after_days` 天 | 有，但是灰的点不动；鼠标移上去说明还差多久 |
| 已停用且停满，但名下还有在用的活动或名单、报名 | 有，也是灰的；提示写清缺什么 |
| 已停用、停满、名下没有在用的东西 | 可以点，超管及以上 + sudo，删掉就找不回来 |

删除时一并收掉：会话、API 令牌、助手存档、头像、活动席位、站内通知、草稿、预设收藏。
**审计不删**：它记的是账号编号，删完那几行显示成 `账号 #10003`，历史与身份还认得出。

已归档的活动不拦着删人：删掉之后那场活动的负责人一栏显示「账号已删除」，取消归档时
需要同时指定新的负责人（见 [活动](events.md)）。名单与报名可以先用「名单管理」转交或者删掉。

## 活动管理

侧栏「活动管理」，超级管理员及以上。

内容区两张表：**当前活动**与**归档的活动**，两张表的列与宽度一致：活动 / 活动号 / 负责人 /
时间（当前活动是创建时间，归档的是归档时间）/ token / 操作。活动名旁边如果挂着红色的
「不可用」胶囊，说明它依赖的模块被停用了（悬停或点一下能看到原因）。
**首列的活动名可以点开**，详情弹窗里是这场活动的高权限操作：

| 动作 | 当前活动 | 已归档 |
| --- | --- | --- |
| 打开活动设置 ↗ | ✓ | — |
| 下载数据 / 下载完整数据 | ✓ | ✓（含归档包） |
| 转移负责人 | ✓ | — |
| 回收站内资源 | ✓ | — |
| 强制归档 | ✓ | — |
| 取消归档 | — | ✓ |
| 彻底删除 | — | ✓ |

除了「打开活动设置 ↗」「转移负责人」（负责人自己做时不需要提权），其余都要进 sudo；
「彻底删除」不可逆。「强制归档」是替别人收东西，属于提权操作；负责人归档**自己**的活动
则不要密码，见 [活动](events.md)。这一页只管高权限动作，不放新建活动一类的常规入口。

**取消归档时负责人账号可能已经不在了**（账号可以被彻底删除，已归档的活动不拦着删人）：
这种活动在负责人一栏写「账号已删除」，点 [取消归档] 会先让你选一个新的负责人，
确认之后转移与恢复一起完成。

## 名单管理

侧栏「名单管理」，超级管理员及以上，就排在「活动管理」下面。做法与活动管理同一套：
内容区两张表，**名单**与**报名**，点名称打开详情，高权限动作都在详情弹窗里。

第一张卡片顶上有一对切换 [当前] [已归档]：**当前**是还在用的名单与报名（默认），
**已归档**是拥有者收起来的那批，这一栏的最后时间列变成归档时间。
**归档等于拥有者那边的删除**——他自己再也看不到，所以这一页是唯一能翻出归档名单与报名的地方
（活动那边同理：「活动管理 › 归档的活动」）。

| 表 | 列 |
| --- | --- |
| 名单 | 名单 / 拥有者 / 可见性 / 人数 / 更新时间 / 操作 |
| 报名 | 报名 / 拥有者 / 状态 / 已报名 / 更新时间 / 操作 |

详情弹窗里的动作，按对象当前在哪一栏决定：

| 在哪一栏 | 动作 |
| --- | --- |
| 当前 | 打开 ↗ / 转移拥有者 / 归档 |
| 已归档 | 取消归档 / 彻底删除 |

- **归档**：把这份名单或报名从拥有者的列表里收起来（拥有者自己也能做，见
  [名单](rosters.md) 与 [报名](signups.md)）。**替别人归档要进 sudo**（用自己的权限动别人的
  数据）；名单上还挂着报名时会再问一句「一并归档？」
- **取消归档**：放回普通列表，拥有者又能打开它（要 sudo）
- **彻底删除**：只对归档过的对象开放，不可逆——这一步是平台唯一的真正删除（要 sudo）
- **转移拥有者**：从选人弹窗里挑一个人，交给他；**原来的拥有者会保留一份写入权限**，
  免得自己建出来的东西被收走之后想改又没门路（要 sudo）

详情弹窗是只读的，点弹窗外面也能关掉。**转移不挪动这份名单或报名**，做完之后详情照旧留着；
归档与彻底删除会给对象换位置或者抹掉它，详情自动收起、两张表随即刷新。取消任何一步都回到详情。

取消归档、转移与彻底删除要进 sudo 并记审计；归档**自己的**那份也不要密码，替别人归档仍然要。
这一页是超级管理员代别人做事的地方，所以这里的动作基本都在提权那一档：没提权时先输一次密码，
已经提权时再问一句就直接做。这一页存在的理由：名单与报名是别人也要用的长期资产，
账号可以被彻底删除，但这些东西得有人接手或者显式清掉。

## 模块管理

侧栏「模块管理」，**只有站长能看到**：装与停都是整台机器的事。内容区一张表：模块 / 版本 /
作者 / 引用计数 / 操作，右上角 [导入模块]，最右一列是 [卸载]（自己装的才有）与 [停用] / [启用]。
「引用计数」是还在用这个模块的活动数。

### 导入

[导入模块] 选一个 zip，里面是模块目录（`module.json` 在最外层，或者整个目录一起打包）。

- 选完先出一张**确认单**：模块名、标识、版本、作者、体积，以及它申请的能力。
  申请了高危能力（`super.` 前缀）时，另起一句红字「模块申请以下高危权限」，逐条列能力与后果
- 这一步还没有装：点 [取消] 什么都不发生。点 [安装] 要再输一次密码（模块的代码会在服务进程里跑）
- 装好之后出现在表里，带「已导入」标记，可以 [停用] 或 [卸载]
- 平台自带的模块不给卸载，也不能用同名的模块顶掉它；装上之后要换版本，先卸载再装
- 不想用界面也行：把目录放进 `modules/`，重启后一样出现在这张表里

### 停用与启用

停用与启用都是**站级动作**：要先进 sudo（输一次密码），并记审计。

- 停用之后，使用这个模块的活动立刻不可用：已经打开的活动页会自己换成一张说明页，
  说明页写着「此活动不可用 / 此活动必需的资源已被管理员停用」；活动接口返回 503。
  「我的活动」的卡片在标题右边多一枚红色「不可用」胶囊，悬停或点一下能看到原因
- 活动数据一条不动。停用的模块也不再出现在创建活动的列表里，它的预设一并标为不可用
- 启用之后这些活动立刻恢复，刷新页面即可；不用重建、不用改配置

### 高危权限

有的模块会申请平台保留的高危能力（`super.` 前缀，例如不受限制的短链跳转）。这类模块在
名字右边挂一枚红色「高危」胶囊，悬停或点一下能看到申请了哪几条：

- **申请即生效**，平台没有"申请了但没用上"这种中间状态；所以提示放在导入那一步——
  装之前就把能力与后果一条条摆出来，看清了再点 [安装]
- 至于模块到底能不能干这件事，靠的是「装没装」：不放心就 [停用] 或者 [卸载]

## 展示屏幕

侧栏「外部资源 › 展示屏幕」。页面右上角 [导入]；内容区三块：可用的屏幕、导入说明、引用方式。

- 「可用的屏幕」列出内置与导入的展示屏幕，各自有标识与体积
- 「导入说明」写着导入要求：包内要有 `screen.html`，只收样式表、脚本与图片，压缩包 2 MB 以内、
  解开后 8 MB 以内
- 活动用哪一份屏幕，在活动后台的「活动设置」里选
