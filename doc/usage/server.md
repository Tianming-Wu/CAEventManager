# 服务器与审计 - 机器占用与操作留痕

这两页只有站长能看到。

## 页面结构

- **服务器管理**：页面右上角 [刷新]；内容区「CPU 占用」「内存占用」「运行时长」
  「用户（在线 / 注册）」「服务信息」「服务」几张卡片
- **审计日志**：一张表格，列是 时间 / 操作人 / 动作 / 对象 / 说明，底部 [加载更多]

## 服务器管理

机器占用、运行时长、用户（在线 / 注册）与版本号都在这一页。顶栏左侧的 CPU 与 MEM 也是它的缩写版。
安全模式下，「服务信息」里的版本号后面带一个「（安全模式）」。

### 服务卡片

内容区「服务」卡片上有两个按钮：

- [重启服务]：确认后服务重启一次，页面自己等它回来再刷新。改了 `config.json` 或换了新版本时用
- [进入安全模式] / [退出安全模式]：同一个位置两态。进入之后活动页显示维护提示、数据不动；
  退出之后活动页恢复开放。进出都会重启一次服务

两个动作要重新输入一次密码。

它们需要服务由 `bin/service.sh` 启动才生效：那种情况下服务跑在它起的看护进程里，能自己重启。
服务是手工起的（直接跑 `bin/run.sh`）时，卡片右边会写着「服务管理未运行，无法自动重启。
详见服务文档」，这时只改配置，重启要到服务器上做，见 [部署与运维](../ops/deploy.md)。

**服务可能自己进安全模式**：连着三次起不来（多半是某份数据或配置坏了），下一次启动会自己
按安全模式起来——这样人还进得来，坏掉的那份数据也不会被反复碰。这时页面与登录页上都有那条
横幅，审计日志里有一笔 `enter_safe_mode`（说明 `reason: multiple crash detected`），
修好之后照常点 [退出安全模式]，见 [部署与运维](../ops/deploy.md) 的「崩溃自检」。

备份与日志不在这一页：每个活动自己那一页有「下载数据」，服务器上的日志用
`bin/service.sh log` 看，见 [../ops/deploy.md](../ops/deploy.md)。

## 审计日志

记每一次写入：谁、什么时候、对哪个对象、改了什么。表中一列一件事，翻到底点「加载更多」。
搜索在服务端完成，所以搜的是全部记录，不只是已经翻出来的这些。

- **操作人**写成「名字 (编号)」，例如 `站长 (10000)`；系统自己做的写 `system (0)`。
  库里存的是编号，改登录名、改显示名都不会影响它
- **说明**一律是 `键: 值` 的写法，多个字段用逗号隔开，例如 `event_id: 9`、
  `ip: 127.0.0.1`、`reason: manual`、`affected: 1`。值可以是中文（人名、活动名照原样放）

审计日志只记改动，不记查看。同一个人带着 API 令牌操作时，操作人仍记本人，
说明后面多一段 `via: token <令牌名>`。

## 活动自己的日志

每个活动后台还有一份自己的操作日志，只记这场活动里的事，给现场复盘用。两者分开：
面板的审计日志是整台机器的账。
