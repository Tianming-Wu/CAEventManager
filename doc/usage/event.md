# 一场活动的现场

一场活动在服务里有两个标识：数字 `seq` 只用于存储，不出现在地址里；`token` 是 32 位访问凭据，
本身就是地址中的一段。所有页面都挂在这个 token 下：

```
/<前缀>/<token>/           公示页（只读，不需要登录）
/<前缀>/<token>/screen     大屏投影
/<前缀>/<token>/checkin    自助签到（必须扫大屏二维码进入）
/<前缀>/<token>/admin      活动后台（用面板账号登录）
/<前缀>/<token>/login      跳到面板登录，登录后回到这个后台
/<s 短码>                  限时短码跳转，由后台生成
```

活动后台没有自己的账号体系：它用面板账号登录，沿用同一个会话 cookie，所以同一个浏览器里不用
输第二次密码。能否进入取决于这个账号是不是本活动的成员（负责人或成员），邀请与确认见
[`panel.md`](panel.md#活动)。

## 公示页

只读，不需要登录，任何人都能打开。显示签到人数、任务完成数、已发奖票与中奖名单。
用于把链接发到群里，或者放在教室门口的屏幕上。

## 大屏

投影用。签到阶段显示签到二维码（按 10 秒窗口切片，过期就换一张）；抽奖阶段换成活动地址与
常驻的中奖名单。抽奖动画播完之前不会因为服务更新而刷新——现场不会看到一半的动画被切断。

大屏是一份可替换的插接件：活动不写就用自带的展示页；站长与超级管理员可以在
「外部资源 › 展示屏幕」导入一份自己的（zip，包内需要 `screen.html`，只接受
`.css .js .svg .png .jpg .jpeg .webp`，包不超过 2 MB、解开后总量不超过 8 MB）。

## 签到

必须扫大屏上的二维码进入：二维码里的 token 有时效，扫码通过后这台手机得到一个签名 cookie，
再填学号与姓名，两项都与名单匹配才算签到成功。这样可以避免把签到页的链接转发出去乱签。

## 操作台

现场用的主页面，一次看全所有人：

- **完成任务**：参与者依次完成 签到 → 任务一 → 任务二。前一环没完成时后面的标记会被拒绝，
  并指出缺哪一步
- **解锁修改**：现场总有例外（设备故障、临时改流程）。打开之后可以越序标记，这一条会在操作日志里
  带上「越序：未完成 ……」的说明——数据留下的是"当时确实这样做了"，而不是把它抹平。
  30 秒无操作自动上锁
- **奖票**：按奖票池规则发放，每张票按顺序发号

## 奖票池

| 模式 | 取值 | 什么时候用 |
| --- | --- | --- |
| 自动 | 到场人数 × 3 + 常数（默认 20） | 跟着真实到场人数走，保底票永远发得出 |
| 固定 | 指定张数 | 印了确定数量实物票时 |
| 表达式 | 例如 `signed_in * 3 + 20` | 需要按现场形状伸缩时 |

表达式由一个小型求值器执行，只允许数字、上下文名字、四则运算与 `min max round abs int`，
没有 `eval`。可用名字：`signed_in`、`present`、`participants`、`staff_present`、`tasks_done`、
`guaranteed`、`bonus_constant`、`pool_size`。池子可以中途上调，也可以下调到不低于已发张数。

## 抽奖

- 每个奖品各有一档**节奏**：逐个（点一次抽出一个人，配合大屏动画）或一次抽完（点一次抽出剩余
  名额，大屏只播一次动画再列出得主）。节奏随奖品保存，换台电脑打开还是这一档
- 两个独立的去重开关，在「奖票设置」里：**同一个奖不重复同一个人**；**一个人不能同时拿两个奖**
- 按人抽取的奖（例如特等奖）只受第一条约束：它不抽票，与按票的奖互不排斥
- 作废一条抽奖记录，这个人即恢复资格
- 材料不够时（可抽的票少于剩余名额）会抽出能抽的部分，并说明原因

## 名单与导出

- 名单页支持 CSV / TSV 导入，有表头自动识别，按学号增量更新，重复导入不留重复记录
- 检索同时匹配姓名、全拼、首字母与学号片段
- 活动结束后从名单页导出 ZIP：`01-汇总`、`02-名单`、`03-奖票明细`、`04-抽奖记录`、
  `05-中奖汇总` 五张 CSV 与 `06-操作日志.log`
- 归档：活动不会消失，存档之后退到「活动管理 › 归档的活动」，标题、负责人、归档时间都留着
