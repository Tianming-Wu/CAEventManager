# CAEventManager

一场学生社团活动在现场要用到的东西：签到、任务进度、奖票发放、抽奖，以及每一次操作的留痕。自托管、
单进程，Python 3 标准库足够，没有第三方运行时依赖；前端是原生 JS，没有构建步骤。同一个进程服务主面板
（账号、活动列表、审批）与每个活动的 token 段（公示页、大屏、签到、控制台），新增活动不改变路径结构。

## 路由

```
/                  主面板登录页（/login 是同一页）
/register          主面板注册（提交后待审核）
/panel             主面板控制台
/panel_static/*    主面板静态资源
/api/panel/*       主面板接口

/<token>/          活动公示页，只读，无鉴权
/<token>/screen    大屏投影页
/<token>/checkin   自助签到，须带 ?t= 时效 token
/<token>/admin     活动控制台，用主面板账号登录
/<token>/login     跳转到主面板登录，登录后回到该活动后台
/s/<code>          限时短码跳转，由控制台生成
```

活动后台没有自己的账号体系：它用主面板账号登录，沿用主面板的会话 cookie，因此同一个浏览器里
不需要输第二次密码。能否进入某个活动的后台，取决于该账号是不是这个活动的负责人或成员。

路由与外部前缀无关：路径里出现已知活动 token 时按活动处理，否则把剩余路径按主面板路由匹配，因此
本机直连、反向代理前缀、将来的子域名都无需改代码。`public_base_prefix` 只用于生成绝对链接
（二维码、分享链接、Cookie 路径），不参与路由判定。

活动有两个标识：数字 `seq` 只用于存储，不出现在 URL 里；`token` 是 32 位 base64url 的访问凭据，
本身就是 URL 中的一段。`path_secret` 是首个活动的 token，可在控制台重新生成，旧链接随即失效。

## 活动页面

公示页只读，展示签到人数、任务完成数、已发奖票与中奖名单。大屏页在签到阶段显示签到二维码，抽奖阶段
改为活动地址与常驻中奖名单。签到页必须扫大屏二维码进入：token 按 10 秒窗口切片，扫码通过后手机得到
签名 presence cookie，再填学号与姓名，两项都与名单匹配才算签到成功。

活动后台的页面栏由两方拼成：活动模块申请自己的页面（操作台、名单、奖票、抽奖、奖票设置），平台
追加「活动设置」与「日志」。活动设置是平台画的，管的是与玩法无关的东西——成员、活动本身的信息。

## 账号与权限

账号分三级：站长（唯一）> 超级管理员 > 管理员。注册一律先落到「管理员 + 待审核」，审核通过才能登录。
用户管理、活动管理、审批只对超级管理员及以上可见，服务器管理与审计日志只对站长可见，接口层同样校验。

敏感操作分两层：轮换活动访问地址、存档活动、封禁或停用账号、修改角色需要重新输入一次密码，进入 sudo
模式后十分钟内不再询问；其余操作（审核、启用、重命名、邀请）只做一次弹窗确认。sudo 模式记在会话上，
同一账号在另一台设备登录不会继承，退出登录或切换账号立即失效。活动后台的「解锁修改」是另一回事，
它管的是现场操作台里的撤销、改时间、删人与重置奖票，30 秒无操作自动上锁。

### 成员

活动后台用主面板账号登录，但能不能进取决于是不是这个活动的成员。负责人在活动后台的「活动设置」
里邀请：按登录名或称呼搜到人、发出邀请，对方在自己的面板「我的活动」里确认一次才算加入。

移出成员不删记录：席位变成「已移出」并留下时间，名单里灰显保留，随时可以重新邀请——重新邀请
同样要对方再确认一次。负责人不能把自己移出，也不能移出活动里唯一的负责人。

## 多会话同步

同一份数据可能同时开着好几个会话：两个管理员、同一人的两台设备，或者现场多位工作人员各自用手机
打开活动后台登记。一处改动会在片刻之内出现在别处，不需要手动刷新。

活动后台是主要的多人场景，对象因此划分得很细——**一个学生就是一个对象**。两位工作人员登记两位
不同的学生互不影响；同一个人被两个人登记时，只要结果相同就算同一件事，不报错。总面板的写法相同，
对象是账号、活动、预设。


- 服务端在每次成功的写入之后把相关对象的版本号加一；两处都通过服务端事件流推送
  （总面板 `GET /api/panel/stream`，活动后台 `/<token>/api/admin/stream`），客户端收到后
  重新读取当前页面；活动后台的 5 秒轮询保留为事件流连不上时的兜底；
- 版本号按对象记（`account:7`、`event:3`、`preset:x.y`），不是整块面板一个号。两个会话改的
  不是同一个对象时，各自成功，互不影响；
- 每个写入请求带上客户端各对象的版本号（`X-Rev-Map`）。只有**同一个对象**被别人先改过、
  且本次要落地的状态与当前状态不同时才算冲突：服务端拒绝（409），界面在右上角提示，并以
  服务端状态为准——先到的写入生效；
- 想要的状态已经是事实时不算冲突：两人先后把同一账号设为同一状态，第二个不报错，服务端保留
  第一个人的时间与操作人。

连接断开不会造成数据不一致：重连后收到的是完整版本号，落后的会话会一次性对齐。

大屏与公示页走同一条事件流（`/<token>/api/stream`，不需要登录），只收本活动的变化，别的活动
的写入会被丢掉。事件流连不上时它们照旧轮询（大屏 1.5 秒、公示 5 秒）；连上之后轮询降为半分钟
一次的对账读取，用来兜住偶发漏收。公示页的读取带 `ETag`，没有变化时服务端回 304、不再重发名单。

## 长列表

可能很长的列表一律分页读取、并且搜索在服务端完成：账号、审计日志、归档活动都是「一次取一页，
按需再取」，页头显示总数。活动自己的名单、奖票、抽奖记录不分页——现场需要一眼看全。

## 奖票池

| 模式 | 取值 | 说明 |
|---|---|---|
| 自动 | `到场人数 × 3 + 常数`（常数默认 20） | 跟着真实到场人数走，保底票永远发得出 |
| 固定 | 指定张数 | 印了确定数量实物票时使用 |
| 表达式 | 例如 `signed_in * 3 + 20` | 每次状态变化重新求值，按现场形状伸缩 |

每张票按顺序发号，与池子大小解耦，因此池子可以中途上调，也可以下调到不低于已发张数。表达式由小型
AST 求值器执行，只允许数字、上下文名字、四则运算与 `min` `max` `round` `abs` `int`，没有 `eval`；
可用名字有 `signed_in`、`present`、`participants`、`staff_present`、`tasks_done`、`guaranteed`、
`bonus_constant`、`pool_size`。

## 任务链

参与者依次完成签到 → 任务一 → 任务二，前一环没有完成时后面的标记会被拒绝，并指出缺哪一步。

现场总会有例外（设备故障、临时改流程）。打开操作台右上角的「解锁修改」之后，管理员可以越序标记，
这一条会在操作日志里带上「越序：未完成 ……」的说明，导出包里的操作日志同样保留——数据上留下的
是"当时确实这样做了"，而不是把它抹平。

## 抽奖去重

两个独立开关，在活动后台的「奖票设置」里：

- **同一个奖不重复同一个人**：一个奖有几个名额，同一个人只会在其中一份里出现。
- **一个人不能同时拿两个奖**：中过任何一个按票抽取的奖之后，此人的票不再进入其它奖项的抽取。

按人抽取的奖（例如特等奖，所有到场者等概率）只受第一条约束：它本来就不是"抽票"，与按票的奖项
互不排斥，中过按票的奖的人也仍可被抽中，反之亦然。

作废一条抽奖记录，该人即恢复资格。

## 抽奖节奏

每个奖品在后台「抽奖」一栏里各有一档「逐个 / 一次抽完」，随奖品一起保存，换台电脑打开也是这一档：

- **逐个**：点一次抽出一个人，配合大屏动画，适合名额少、要仪式感的奖。
- **一次抽完**：点一次抽出该奖品的全部剩余名额，适合名额多的小奖，省时间。

一次抽完仍然是一张票一张票地消耗，作废规则与两个去重开关都不变；大屏收到整批结果后只播一次动画，
再把这一批的得主一次列出来。材料不够时（例如可抽的票少于剩余名额）会抽出能抽的部分并说明原因。

## 名单与导出

名单支持 CSV 与 TSV 导入，有表头自动识别，无表头按「学号,姓名」解析，按学号增量更新，重复导入不留
重复记录。姓名拼音由内置拼音表生成，检索同时匹配姓名、全拼、首字母与学号片段。所有动作写入审计日志；
活动结束后从名单页导出 ZIP：`01-汇总`、`02-名单`、`03-奖票明细`、`04-抽奖记录`、`05-中奖汇总`
五张 CSV 与 `06-操作日志.log`。

## 归档

活动不会消失：存档之后它从列表里退到「活动管理 › 归档的活动」，标题、负责人、归档时间都留着，
数据库文件不动。归档是带 sudo 的操作，所以那边不再给"取消归档"按钮——要做也是另一次显式操作。

归档列表是分页的（一次 20 条，按需再取），不会把历年的活动一次全读出来。

## 活动模块与预设

`modules/<id>/` 下放 `module.json`（标识、名称、版本、兼容约束、页面清单）与 `schema.json`（创建时定下的
参数）。创建活动的表单由 schema 生成，取值校验通过后写进该活动自己的库；兼容约束按本版本号判定，不满足
的模块不出现在创建列表里。`templates/<id>.json` 是模块之上的一种安排：选定模块并预填参数或默认活动名，
只能设置模块已声明的参数，写别的键会被拒绝。

### 模块与预设的关系

模块是**能力边界**：装上并启用某个模块，才有它允许的那些设置与页面；停用之后引用仍然保留，只是不能再
拿它开新活动（已开的活动不受影响，成员、成绩这些照旧可读）。

预设是**边界之内的一个练好的配置**：模块的参数很多，一项项调到想要的效果要费工夫，预设把其中一种调好
的结果存下来，下次换名称和人数就能开。所以预设一定依赖某个模块，也可以依赖另一个预设（在它的基础上改）。

```
builtin/modules/<模块>/module.json     模块本体
builtin/modules/<模块>/templates/*.json  随模块发布的预设
builtin/templates/*.json               随版本发布的预设
modules/, templates/                   本实例自己装的，不进版本库
```

预设文件里的依赖写成：

```json
"dependency": { "module": "nwuca.lottery", "template": "nwuca.lottery.salon" }
```

导入一个预设时，如果它依赖的模块不存在（或被停用），会先说清楚，再由人决定是否仍然导入；导入之后它
照常列出，只是标为不可用。

### 预设

预设是一份**存下来的活动配置**：用哪个模块、那套参数、以及建议的活动名称。它不是"可配置项清单"，
而是某个活动当时的设定快照——在活动卡片菜单里「保存为预设」，下次建活动时挑一份，改改名称和人数
就能开下一场。

预设分三处：我收藏的、我创建的、预设广场。可见性三档：私有（只有自己）、公开（广场里所有人）、
组织公开（组织建好之后只对本组织可见，目前按公开处理）。内置预设来自 `templates/*.json`，启动时
同步进数据库，所以列表只有一个来源。

## 部署

目标是一台能 ssh 的 Linux 主机，只需要 python3 与 tar。

```powershell
.\deploy.ps1 -Remote user@host              # 上传并重启
.\deploy.ps1 -Remote user@host -NoRestart   # 只同步，远端目录默认 ~/apps/eventmanager
```

脚本归一化行尾后打包源码，用 base64 经 ssh stdin 送出（目标机没有 sftp），远端解包，逐个确认文件落地
并试 import 主模块，全部通过才重启；远端的 `data/` 与 `config.json` 始终不动。

```sh
cd ~/apps/eventmanager
./service.sh status            # 打印公示 / 大屏 / 控制台三个地址，活动前先跑一次
./service.sh start|stop|restart
./service.sh log 50            # 另有 check / reset
```

服务不会自动拉起。挂载在 `https://example.org/mount` 时，活动页形如 `https://example.org/mount/<token>/`，
大屏、签到、控制台是同前缀下的 `screen`、`checkin`、`admin`。部署后可用 `tools/` 下的脚本自检：`unit_test.py`
无需服务，`panel_test.py` 打主面板接口，`smoke_test.py` 打活动接口，`panel_ui_test.py` 与 `ui_test.py`
用 Playwright 驱动真实页面。

## 配置

`config.json` 位于仓库根目录，首次启动时自动写入。

| 键 | 默认值 | 作用 |
|---|---|---|
| `path_secret` | 自动生成 | 首个活动的访问 token，也是它的 URL 段 |
| `host` | `0.0.0.0` | 监听地址 |
| `port` | `8931` | 监听端口 |
| `public_base_prefix` | `http://127.0.0.1:8931` | 对外访问前缀，只用于拼绝对链接 |
| `owner_username` | `owner` | 站长登录名 |
| `owner_name` | `站长` | 站长显示名，界面只出现这个 |

活动标题、奖票池、奖品、大屏阶段、导出时区等属于单个活动，存在该活动自己的库里，不进 `config.json`。
环境变量可覆盖：`LOTTERY_CONFIG`、`LOTTERY_DATA_DIR`、`LOTTERY_HOST`、`LOTTERY_PORT`。数据目录中，
`data/panel.sqlite3` 存账号与活动元数据，`data/events/<seq>.sqlite3` 是每个活动自己的库，`data/avatars/`
存头像，首次启动生成的站长密码在 `data/owner_password.txt`。
