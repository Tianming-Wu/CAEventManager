# 通知与服务提示 - 铃铛与降级提示

右上角的铃铛是通知中心。两类东西排在同一个列表里：别人发来的通知，以及服务自己的状态提示。

## 页面结构

顶栏右侧的 [通知（铃铛图标）] 点开后，通知中心从顶栏下方滑出：一块通知列表，底部 [全部已读]。
紧急级另有一个弹窗，只有 [已读] 与 [关闭] 两个按钮。

## 通知

有未读时铃铛上出现圆点。「全部已读」清空未读，单条点开即标为已读。

有服务提示时铃铛本身变成强调色。红点仍然是"有未读通知"的意思，不受服务提示影响。

紧急级的未读会在登录后单独弹出一次，点「已读」或「关闭」才结束——点周围不会关掉它。
「关闭」只是收起，没有标已读，下次登录还会弹。

## 服务提示

服务降级的时候，列表最上面会出现一条服务提示：

| 什么时候出现 | 会不会自己消失 |
| --- | --- |
| CPU 占用偏高、内存占用偏高 | 会。占用降下来它就没了 |
| 数据盘空间不足 | 不会。要清理到阈值以上才消失，也可以点「不再提示」 |
| 数据盘空间几乎用尽 | 不会，也不给关这一条 |

它的正文写着当时的读数，例如「只剩 4.2 GB（8%）。空间用尽后，报名、签到与操作记录都写不进去」。
提示由服务按当时的读数推出来：情况好转，提示自己就走了，不需要谁来处理。

活动后台的右上角也有同样一条，鼠标停留在提示上可显示说明。

## 自己排一条通知

站长可以在服务器上直接排：

```sh
python tools/notify.py "周末活动报名已开放" "报名截止到周五 18:00。"
python tools/notify.py "今晚维护" --level critical
python tools/notify.py "你的名单已批" --account laffey
```

第一个参数是标题，第二个是正文（可省）。默认发给所有人，`--account` 只发给一个人，
`--level critical` 走紧急那一档。换一份数据目录用 `--data-dir`。
