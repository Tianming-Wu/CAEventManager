# 活动 - 创建、成员与存档

活动是这套系统的中心：一场比赛、一次抽奖、一次报名，都建一个活动。活动的页面与设置由它所用的
**模块**提供，平台只提供框架。

## 页面结构

- **我的活动**：页面右上角 [创建活动]；内容区分三块——待处理的邀请、我创建的活动、我参与的活动。
  一场活动一张卡片，卡片上有菜单 [更多（三个点图标）]，保存为预设等操作在那里
- **创建活动**：一整页，分「基础信息」「预设」「成员」「活动设定」四张卡片，底部 [创建活动]；
  卡片区上方另有 [导入配置]
- **活动管理**（超级管理员及以上）：当前活动、归档的活动两块

## 我的活动

三块：待处理的邀请、我创建的活动、我参与的活动。点击卡片上的 「管理面板」进入活动后台。

超级管理员及以上在「活动管理」里可以看到全部活动，包括已经归档的活动。

## 创建活动

「我的活动 › 创建活动」：选择一种活动形式，并填写创建时参数。
等待审批：当前版本未实现，所有活动创建自动通过，不需要经过审批。
创建活动后，当前账号是负责人身份，自动在新标签页打开活动后台。

模块是能力边界：换一种玩法就换一个模块，模块之间没有关系。

## 邀请成员

两个入口，功能一致：活动后台「活动设置 › 成员」右上角的 [邀请成员]，以及「创建活动」页的快速邀请卡片。
点击可以打开人员选择器。确认邀请后，对方在自己的「我的活动 › 待处理的邀请」里确认之后生效。

在发送邀请到对方确认邀请前，邀请人可以随时撤回邀请。撤回后对方的待处理邀请消失。

- 只显示显示名与头像，不显示任何人的登录名
- 移出不删记录：席位变成「已移出」并留下时间，随时可以重新邀请
- 负责人不能把自己移出，也不能移出活动里唯一的负责人

可以在「活动管理 › 活动详情 › 转移负责人」中将负责人转移给其他用户。

## 归档

对用户来说，活动没有「删除」，只有归档。归档是**活动负责人**对自己活动的软删除。

- 归档时服务端把这场活动的整个文件夹打包、只留一份元数据，活动从列表退到「活动管理 › 归档的活动」
- 归档会触发站内资源的回收：**短链全部销毁**（不管是过期、次数用尽、被超管删掉还是随活动归档，
  短链随时可能被平台回收）。取消归档**不会**把这些短链还回来
- **归档之后不再保证活动还能打开**：要留数据就在归档前下载
- 归档不是 sudo 操作：点 [归档] 后仅触发二次确认。见 [sudo 模式](sudo.md)。

### 下载数据

活动正常开启时，负责人与参与者都可以在活动详情内使用「下载数据」功能，获得生产数据快照。
以 zip 格式提供，包含业务库、审计日志与元数据。

### 归档之后

归档之后活动不再由负责人管理，活动对负责人不再可见。

要对归档后的活动进行操作，需要超级管理员以上权限，在「活动管理 › 活动详情」里执行：

| 动作 | 权限 | 说明 |
| --- | --- | --- |
| 取消归档 | 超管及以上 (sudo) | 把归档包解开，活动恢复可打开，负责人就能下载 |
| 下载完整数据 | 超管及以上 (sudo) | 服务器上关于这场活动的全部内容，含归档包 |
| 彻底删除 | 超管及以上 (sudo) | 不可逆 |

负责人忘了在归档前下载数据时，可以自行联系超管取消归档。

这三个动作都在「活动管理 › 活动详情」弹窗里执行。弹窗是只读的，点弹窗外面也能关掉。

已经归档的活动不会阻止账号被删除，见 [平台管理页](platform-pages.md)。

如果取消归档时，活动负责人账号已经不可使用，则操作时需要先行指定一个新的负责人账号。
指定后，活动恢复后就归新负责人管理。

## 活动后台

活动后台使用面板账号登录，可以自动使用主站的会话信息，无需重复登录。
鉴权仍然进行。活动后台属于主站的操作仍然遵循主站的权限规则。

平台的页面（活动设置、日志）见 [event-site.md](event-site.md)；
模块自己的页面写在模块的说明里。
