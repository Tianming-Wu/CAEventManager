# 活动页面与现场 - 地址、大屏、签到与日志

活动的内容是**模块**：装上并启用某个模块，才有它的页面与设置。平台自己只提供每个活动都有的
那几页（公示页、大屏、签到、活动设置、日志），模块往活动后台里加自己的页面。

## 活动后台的页面

顶栏左边是活动名称与「后台」，右边依次是：解锁修改开关、[大屏 ↗]、[公示 ↗]、登录账号、[退出]。

页签由模块与平台拼成：内置的奖票抽奖是 操作台 / 名单 / 奖票 / 抽奖 / 奖票设置，
平台始终追加 活动设置 与 日志。模块页签里的内容见模块自己的 doc.md。

这一页没有侧栏：宽度不足 640px 时，顶栏按钮挤在一起、页面左右内边距收窄，页签可以横向滑动。
面板那边的三档布局见 [start.md](start.md)。

## 地址

```
/<token>/           公示页（只读，不需要登录）
/<token>/screen     大屏投影
/<token>/checkin    自助签到（必须扫大屏二维码进入）
/<token>/admin      活动后台（用面板账号登录）
/<token>/login      跳到面板登录，登录后回到这个后台
/s/<短码>            限时短码跳转，由后台生成
```

`<token>` 是 32 位访问凭据，本身就是地址里的一段。数字序号只用于存储，不出现在地址里。
服务挂在子路径下时，前面还会多一段部署前缀——那是服务的地址，与活动无关。

活动后台沿用面板账号与会话，谁能进见 [events.md](events.md)。

## 公示页

只读，不需要登录，任何人都能打开。显示签到人数、任务完成数、已发奖票与中奖名单。
用于把链接发到群里，或者放在教室门口的屏幕上。

## 大屏

投影用。签到阶段显示签到二维码（按 10 秒窗口切片，过期就换一张）；抽奖阶段换成活动地址与
常驻的中奖名单。抽奖动画播完之前不会因为服务更新而刷新——现场不会看到一半的动画被切断。

大屏是一份可替换的插接件：活动不写就用自带的展示页。站长与超级管理员可以在
「外部资源 › 展示屏幕」导入一份自己的（zip，包内需要 `screen.html`，只接受
`.css .js .svg .png .jpg .jpeg .webp`，包不超过 2 MB、解开后总量不超过 8 MB）。

## 签到

必须扫大屏上的二维码进入：二维码里的凭据有时效，扫码通过后这台手机得到一个签名 cookie，
再填学号与姓名，两项都与名单匹配才算签到成功。这样可以避免把签到页的链接转发出去乱签。

站长可以在活动设置里关掉自助签到。

## 活动设置

平台画的，管的是与玩法无关的东西：

- **成员**：见 [events.md](events.md)
- **活动本身**：名称、访问地址。重新生成地址后旧链接立即失效，需要重新输一次密码
- **展示屏幕**：这个活动用哪一份大屏

## 日志

活动自己的操作日志：谁在什么时候改了什么。与面板的审计日志分开，这一页是给现场复盘用的。

服务降级时，后台右上角会出现一条提示（占用偏高、盘快写不进去了），鼠标停留在提示上可显示说明，
见 [notices.md](notices.md)。

## 模块自己的页面

模块的页面、现场怎么操作、用哪台设备，写在模块自己的说明里：

- 内置的「奖票抽奖」模块：`builtin/modules/nwuca.lottery/doc.md`
- 实例自己装的模块：`modules/<模块 id>/doc.md`

这些说明随应用一起装到机器上，运维助手也能读，所以问「操作台的搜索怎么用」时，
它查到的是模块自己写的那一段。
