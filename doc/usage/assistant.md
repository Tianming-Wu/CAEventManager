# 运维助手

「总览」下面的运维助手用对话查平台上的事：某场活动为什么没人报名、名单里有没有这个人、
最近谁改过东西。

它不绕过权限：助手用的就是当前账号的会话，所以它能看到的、能做的，与本人手点出来完全一致。
普通管理员问到审计日志与服务器状态时，它连这些工具都看不到（清单里没有），不会去撞权限墙。

## 先配模型

一次对话要发到你自己选的模型端点上，所以每个账号各配一份：

| 项 | 说明 |
| --- | --- |
| 接口地址 | 兼容 OpenAI 的端点，例如 `https://api.deepseek.com`。留空用默认值 |
| 模型 | 例如 `deepseek-flash`。留空用默认值；点「获取模型」会问一次服务端，把可选模型列出来 |
| 密钥 | 只写不读。留空表示保持现状；清除请点下面的按钮 |

密钥在服务端使用，浏览器拿不到它，也不会出现在对话、日志与审计里。

## 怎么问

- 直接描述要办的事，例如「上周的活动为什么报名这么少」「帮我查 2024001 在不在动漫社名单里」
- 一轮对话最多来回六步工具调用；过程里调了哪些工具，以小标签显示在回答上方
- 回答里可以带列表与代码块，按最简 Markdown 渲染
- 助手只回答平台范围内的事，超出范围会说清楚

## 它能做什么

目前开放的都是**只读**工具：

| 工具 | 作用 | 谁能用 |
| --- | --- | --- |
| `list_events` | 列出这个账号能看到的活动（含自己在其中的角色） | 所有人 |
| `event_board` | 读一场活动的公示数据：人数、签到、奖票、奖品与最近中奖 | 所有人 |
| `list_rosters` | 列出名单（我参与的 / 我创建的 / 全部） | 所有人 |
| `roster_entries` | 读一份名单里的成员，可按学号或姓名过滤 | 所有人 |
| `list_signups` | 列出报名项：状态、已报人数、名额、写进哪份名单 | 所有人 |
| `signup_entries` | 读一次报名的提交记录 | 所有人 |
| `search_people` | 在平台人员库里按学号或姓名找人 | 所有人 |
| `list_docs` | 列出随应用装好的说明文档（以及各模块的现场说明） | 所有人 |
| `read_doc` | 读其中一份文档的正文 | 所有人 |
| `recent_audit` | 最近的审计日志 | 超级管理员及以上 |
| `host_stats` | 服务器状态与在线人数 | 仅站长 |

**改数据的动作一律不开放**：助手会告诉你去哪个页面操作。改动要么走界面的二次确认，
要么等策略层想清楚。

## 它会查文档

随应用装好的说明文档它都能读：先 `list_docs` 看清单，再 `read_doc` 读其中一份。问到
「这个页面在哪」「字段什么意思」「怎么备份」「操作台的搜索怎么用」时，它去读对应的一份，
而不是凭印象编。模块自己的说明也在清单里。

读文档是只读、有上限的：一次最多读 12000 字（超了就截断并说明），只认清单里出现过的路径。
文档里没有凭据。

## 对话存档

- 对话按会话存下来，下次回来接着聊。输入框上方那条是当前会话的名字，点开是会话列表
  （左侧抽屉），可以改名、删除、导出 Markdown
- 会话 id 在地址里（`.../panel#/assistant/<id>`）：开几个标签页就是几段互不打扰的对话
- 每个账号有一份存档配额（默认 512 KB）。满了不再存新的，页面会提示清理；不够用的人由站长在
  「用户管理」里单独调，那里也能看到某人已经存了多少
- 新会话存下之后会请模型起一个短名字（不超过 12 个字）；起不出来就留着第一句话
