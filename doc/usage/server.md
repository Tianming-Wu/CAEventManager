# 服务器与审计 - 机器占用与操作留痕

这两页只有站长能看到。

## 页面结构

- **服务器管理**：页面右上角 [刷新]；内容区「CPU 占用」「内存占用」「运行时长」
  「用户（在线 / 注册）」「服务信息」「操作」「备份」几张卡片
- **审计日志**：一张表格，列是 时间 / 操作人 / 动作 / 对象 / 说明，底部 [加载更多]

## 服务器管理

机器占用、运行时长、用户（在线 / 注册）与版本号都在这一页。顶栏左侧的 CPU 与 MEM 也是它的缩写版。
安全模式下，「服务信息」里的版本号后面带一个「（安全模式）」。

### 操作卡片

内容区「操作」卡片上有两个按钮：

- [重启服务]：确认后服务重启一次，页面自己等它回来再刷新。改了 `config.json` 或换了新版本时用
- [进入安全模式] / [退出安全模式]：同一个位置两态。进入之后活动页显示维护提示、数据不动；
  退出之后活动页恢复开放。进出都会重启一次服务

两个动作要重新输入一次密码。

它们需要服务由 `bin/service.sh` 启动才生效：那种情况下服务跑在它起的看护进程里，能自己重启。
服务是手工起的（直接跑 `bin/run.sh`）时，卡片右边会写着「服务管理未运行，无法自动重启。
详见服务文档」，这时只改配置，重启要到服务器上做，见 [部署与运维](../ops/deploy.md)。

**服务可能自己进安全模式**：连着三次起不来（多半是某份数据或配置坏了），下一次启动会自己
按安全模式起来——这样人还进得来，坏掉的那份数据也不会被反复碰。这时页面与登录页上都有那条
横幅，审计日志里有一笔 `enter_safe_mode`（说明 `reason: multiple crash detected`），
修好之后照常点 [退出安全模式]，见 [部署与运维](../ops/deploy.md) 的「崩溃自检」。

备份与日志不在这一页：每个活动自己那一页有「下载数据」，服务器上的日志用
`bin/service.sh log` 看，见 [../ops/deploy.md](../ops/deploy.md)。

### 备份卡片

内容区「备份」卡片是备份功能的开关与观测口：

- 一行状态说明计划时间内的备份是否已经执行，以及最近一次备份的时间；尚无备份时写明「尚无备份」。
  有问题时下面紧跟一条提示（备份多久没有执行、某个活动既无业务库也无归档包之类）
- **自动备份** 开关：开启后每天执行一次，关闭后仅手动执行。**调度方式** 为「每天」或「手动」，
  **触发时刻** 填 `HH:MM`
- **留存** 分 **留存天数**、**留存周数**、**留存月数** 三项，另有 **总字节上限**（0 表示不限）。
  最近 24 小时内的备份与"恢复前自动留下的备份"不会被清除
- **WebDAV（异地副本）** 收在折叠区：**启用**、集合地址、子目录、用户名、密码
  （已保存的密码不回显，修改时重新填写）、上传后校验大小、远端随本地清理；另有 [测试 WebDAV]
- 最下面一张表列出现有备份：名称、时间、大小、种类（手动 / 自动 / 恢复前）、活动数量
- [立即备份] 立即执行一次备份；[保存设置] 保存设置，**需要重新输入一次密码**
- 每一次备份都进审计日志，操作人是服务自己（`service (1)`），动作写 `backup`，
  说明里带 `result`、`reason`（`routine` 到点自动、`manual` 手动、`pre-restore` 恢复前）、
  包名、字节数与活动数。恢复这件事本身也记一条，动作写 `restore`
- 备份包存放在服务器上的 `backups/` 目录（必要时由运维用 `backups_dir` 改到其他盘）。
  **恢复不在这一页**：需要停止服务、从命令行执行，见 [部署与运维](../ops/deploy.md) 的「备份与恢复」

## 审计日志

记每一次写入：谁、什么时候、对哪个对象、改了什么。表中一列一件事，翻到底点「加载更多」。
搜索在服务端完成，所以搜的是全部记录，不只是已经翻出来的那些。

- **操作人**写成「名字 (编号)」，例如 `站长 (10000)`；平台自己做的写 `system (0)`，
  服务自己做的（定时备份这类后台动作）写 `service (1)`。库里存的是编号，
  改登录名、改显示名都不会影响它
- **说明**一律是 `键: 值` 的写法，多个字段用逗号隔开，例如 `event_id: 9`、
  `ip: 127.0.0.1`、`reason: manual`、`affected: 1`。值可以是中文（人名、活动名照原样放）

审计日志只记改动，不记查看。同一个人带着 API 令牌操作时，操作人仍记本人，
说明后面多一段 `via: token <令牌名>`。

说明里的 `ip` 是请求的来源地址。服务前面挂着反向代理时，这一栏要么是代理自己的地址，
要么是真实客户端地址，由运维在 `config.json` 的 `trust_forwarded_ip` 决定，见
[部署与运维](../ops/deploy.md#配置)。

## 活动自己的日志

每个活动后台还有一份自己的操作日志，只记这场活动里的事，给现场复盘用。两者分开：
面板的审计日志是整台机器的账。
