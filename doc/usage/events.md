# 活动 - 创建、成员与存档

活动是这套系统的中心：一场比赛、一次抽奖、一次报名，都建一个活动。活动的页面与设置由它所用的
**模块**提供，平台只提供每个活动都有的那几页。

## 页面结构

- **我的活动**：页面右上角 [创建活动]；内容区分三块——待处理的邀请、我创建的活动、我参与的活动。
  一场活动一张卡片，卡片上有菜单 [更多（三个点图标）]，保存为预设等操作在那里
- **创建活动**：一整页，分「基础信息」「预设」「成员」「活动设定」四张卡片，底部 [创建活动]；
  卡片区上方另有 [导入配置]
- **活动管理**（超级管理员及以上）：当前活动、归档的活动两块

## 我的活动

三块：待处理的邀请、我创建的活动、我参与的活动。点卡片进活动后台。

超级管理员及以上在「活动管理」里还能看到全部活动与归档的活动。

## 创建活动

「我的活动 › 创建活动」：选一种活动形式（模块），再填这套形式要的参数。创建出来的是负责人身份，
直接进入活动后台。

模块是能力边界：换一种玩法就换一个模块，模块之间没有关系。

## 邀请成员

在活动后台的「活动设置」里按登录名或称呼搜人、发出邀请。对方在自己的「我的活动 › 待处理的邀请」
里确认一次才算加入。

- 移出不删记录：席位变成「已移出」并留下时间，随时可以重新邀请
- 负责人不能把自己移出，也不能移出活动里唯一的负责人

## 归档

活动没有「删除」，只有归档。归档是**活动负责人**对自己活动的软删除。

- 归档时服务端把这场活动的整个文件夹打包、只留一份元数据，活动从列表退到「活动管理 › 归档的活动」
- 归档会触发站内资源的回收：**短链全部销毁**（不管是过期、次数用尽、被超管删掉还是随活动归档，
  短链随时可能被平台回收）。取消归档**不会**把这些短链还回来
- **归档之后不再保证活动还能打开**：要留数据就在归档前下载
- 归档要重新输入一次密码

### 下载数据

活动正常开启时，负责人与参与者都能在活动详情里「下载数据」，拿到一个 zip：
业务库、审计日志与元数据。

### 归档之后

归档之后这场活动不归负责人管了。要拿数据或者彻底删掉，得找超级管理员：

| 动作 | 谁 | 说明 |
| --- | --- | --- |
| 取消归档 | 超管及以上，提权操作 | 把归档包解开，活动恢复可打开，负责人就能下载 |
| 下载完整数据 | 超管及以上，提权操作 | 服务器上关于这场活动的全部内容，含归档包 |
| 彻底删除 | 超管及以上，提权操作 | 不可逆 |

负责人忘了在归档前下载数据时，就是请超管取消归档，下载完再归一次。

## 活动后台

活动后台没有自己的账号体系：它用面板账号登录，沿用同一个会话，所以同一个浏览器里不用输第二次
密码。能不能进去取决于这个账号是不是本活动的成员。

平台的页面（公示页、大屏、签到、活动设置、日志）见 [event-site.md](event-site.md)；
模块自己的页面写在模块的说明里。
