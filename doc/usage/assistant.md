# 运维助手

「总览」下面的**运维助手**用对话查平台上的事：某场活动为什么没人报名、名单里有没有这个人、
最近谁改过东西。它不绕过权限——助手用的就是当前账号的会话，所以它能看到的、能做的，与本人
手点出来完全一致。

## 先配模型

一次对话要发到你自己选的模型端点上，所以每个账号各配一份：

| 项 | 说明 |
| --- | --- |
| 接口地址 | 兼容 OpenAI 的端点，例如 `https://api.deepseek.com`。留空用默认值 |
| 模型 | 例如 `deepseek-flash`。留空用默认值；点「获取模型」会问一次服务端的 `/models` 把可选模型列出来 |
| 密钥 | 只写不读：保存后输入框里放一串星号（假内容），再保存不会被清掉；要换就直接覆盖，要删就点「清除密钥」。接口永远不回传密钥 |

密钥在服务端使用，浏览器拿不到它，也不会出现在对话、日志与审计里。

## 怎么问

- 直接描述要办的事即可，例如「上周的活动为什么报名这么少」「帮我查 2024001 在不在动漫社名单里」
  「最近谁改过东西」
- 一轮对话最多来回六步工具调用；过程里调了哪些工具，会以小标签显示在回答上方
- 回答里可以带列表与代码块，按最简 Markdown 渲染
- 助手只回答平台范围内的事；超出范围会说清楚

## 它能做什么

目前开放的都是**只读**工具：

| 工具 | 作用 | 谁能用 |
| --- | --- | --- |
| `list_events` | 列出这个账号能看到的活动（含自己在其中的角色） | 所有人 |
| `event_board` | 读一场活动的公示数据：人数、签到、奖票、奖品与最近中奖 | 所有人 |
| `list_rosters` | 列出名单（我参与的 / 我创建的 / 全部） | 所有人 |
| `roster_entries` | 读一份名单里的成员，可按学号或姓名过滤 | 所有人 |
| `list_signups` | 列出报名项：状态、已报人数、名额、写进哪份名单 | 所有人 |
| `signup_entries` | 读一次报名的提交记录 | 所有人 |
| `search_people` | 在平台人员库里按学号或姓名找人 | 所有人 |
| `recent_audit` | 最近的审计日志 | 超级管理员及以上 |
| `host_stats` | 服务器状态与在线人数 | 仅站长 |

看不到的工具**不会出现在发给模型的清单里**——普通管理员的请求里连"有审计日志这个工具"都不知道，
所以它不会去撞权限墙。

**改数据的动作一律不开放**：助手会告诉你去哪个页面操作。这是刻意的——改动要么走界面的二次确认，
要么等策略层想清楚（见 [`../design/assistant.md`](../design/assistant.md)）。

## 对话存档

- 对话按**会话**存下来，下次回来接着聊。输入框上方那一条是当前会话的名字，点开是会话列表
  （左侧抽屉），可以改名、删除、导出 Markdown
- 会话 id 在地址里（`.../panel#/assistant/<id>`）：开几个标签页就是几段互不打扰的对话
- 每个账号有一份**存档配额**（默认 512 KB）。满了不再存新的，页面会提示清理；不够用的人由站长在
  「用户管理」里单独调，那里也能看到某人已经存了多少
- 新会话存下之后会请模型起一个短名字（不超过 12 个字）；起不出来就留着第一句话

## 平台提示词

平台自己的规矩（称呼、语气、本社团的固定说法）写在服务端的一份 markdown 里，手工维护：

```
<数据目录>/assistant_prompt.md          # 线上：~/apps/lottery/data/assistant_prompt.md
```

- 内容是**追加**在固定规则之后发出去的，不用重抄那些规则；文件不在、空着、读不动，就当没有
- 按修改时间缓存：存盘后**下一句话**就带上新内容，不用重启服务
- 上限 20 KB，多出截掉；想放到别处可以用环境变量 `LOTTERY_ASSISTANT_PROMPT` 指一个绝对路径
- 只读：程序不写它，界面上也没有入口

固定规则之外，系统提示里还会写一句「当前使用者：站长（owner）。」——写语气、称呼类的提示词时
这是前提。

### 可以写的变量

发出去之前按**这次对话的人**替换：

| 写法 | 换成 |
| --- | --- |
| `${user.username}` | 登录名 |
| `${user.name}` | 称呼（没填就是登录名） |
| `${user.role}` | 身份：站长 / 超级管理员 / 管理员 |
| `${user.roleKey}` | `owner` / `superadmin` / `admin`（想按身份分头交代时用） |
| `${user.id}` | 账号 id |
| `${panel.name}` | CAEventManager |
| `${panel.version}` | 版本号，例如 `1.7.0.21` |
| `${tools}` | 这个账号能用的工具名，顿号隔开 |
| `${time.date}` | 2026-11-07 |
| `${time.time}` | 20:42 |
| `${time.now}` | 2026-11-07 20:42 |

没写到的占位符**原样留着**——写错能一眼看见，不会悄悄变成空白。

### 例子

```markdown
## 我们这边怎么说

- 把「活动」称作「场次」，把「名单」称作「名册」。
- 对 ${user.role} 说话不用加"您"，平实一点。

## 回答的规矩

- 先给结论，再给依据；涉及数字时把口径写清楚（例如"签到 47 / 名单 63"）。
- 拿不准就问一句，不要替人决定。
- 需要改动时，告诉对方去「名单与报名 › 我的名单」这类具体页面点哪个按钮。
```
