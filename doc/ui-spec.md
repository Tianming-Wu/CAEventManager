# 界面规范（管理面板与活动后台）

写于 2026-11-05。这份文件解决一个反复出现的问题：同一个东西在不同页面长得不一样。
以后新做页面，先照这里排；这里没写的，先补一条再动手。

## 一、页面标题与返回

- 标题让位给返回键，动的是 `padding-left`（0 ↔ 36px），**必须是布局动画**：副标题
  `.page-sub` 与标题在同一行，只有布局变化才会带着它一起挪。用 `transform` 只动标题本身，
  帧内就会叠字或中间空一块
- 这段动画什么时候开始由 JS 定：先摆成上一页的样子，等这一页的内容画完再放开
  （`PX.afterApi` + `requestIdleCallback`）。一屏新表单的排版要几十毫秒，动画撞进去会被
  冻住再跳过去——看起来就是"抽一下"
- 判据写在测试里：`tools/panel_ui_test.py` 的 `crumb_motion` 逐帧量标题与副标题，
  单帧位移不超过 6px、两者位移差不超过 1.5px

每一页都以 `<header class="page-head">` 开头，结构固定三种：

**1. 一级页**（侧栏直接进得来）：只有标题与副标题，右侧可选主操作。

```html
<header class="page-head">
  <h1>我的名单</h1>
  <p class="page-sub">可重复使用的成员名单，例如社团成员、参赛选手</p>
  <div class="page-actions">
    <button class="btn" type="button">导入名单</button>
    <button class="btn primary" type="button">新建名单</button>
  </div>
</header>
```

### 「有没有返回键」由路由表决定

面板的路由表里每条路由可以声明一个 `parent`（上一级）：

```js
"roster":  { parent: { href: "#/rosters",  label: "我的名单" } },
"signup":  { parent: { href: "#/signups",  label: "我的报名" } },
"write-approvals": { parent: { href: "#/rosters", label: "我的名单" } },
```

规则：

- **有 `parent` 的页面永远有返回键**，不因为"这次是从哪里点进来的"而变。名单详情、报名详情
  都属于这一类
- 顶层页（没有 `parent`，例如「写入审批」这种汇总页）默认**没有**返回键；从别的页面跳过来时
  地址里带 `?back=`，才临时给一个返回键，回到跳过来的那一页
- 这种"临时返回键"只出现箭头，**不写面包屑上一级**：标题就是这一页自己的名字（`‹ 写入审批`）
- 地址里的 `?back=` 只决定**返回到哪里**（从别的页面跳过来时回到那一页），不决定有没有返回键；
  没带 `?back=` 就回到 `parent`
- 面包屑的文字与链接也从路由表来，页面标记里不再各写一份
- 切换页面时：两页都有返回键（或都没有）→ 不放动画；由无到有 / 由有到无 → 标题横向滑让位，
  返回键淡入放大 / 淡出缩小（从后方升起的观感）。返回键本身不跟标题一起平移

**2. 二级页（从列表点进来的详情）**：左上角**一个圆角返回箭头**，标题变成面包屑。
返回键永远在最左边，永远是这个样式，不用文字按钮、不用右上角「返回列表」。

```html
<div class="head-title">
  <button class="icon-btn crumb-back" id="rosterBack" type="button"
          aria-label="回到我的名单" title="回到我的名单">
    <svg viewBox="0 0 20 20" aria-hidden="true"><path d="M12 5l-5 5 5 5"/></svg>
  </button>
  <h1 class="crumb-title">
    <a class="crumb" href="#/rosters">我的名单</a>
    <span class="crumb-sep" aria-hidden="true">›</span>
    <span>名单名</span>
  </h1>
</div>
<p class="page-sub">副标题写状态与归属，例如「拥有者：你 · 私有 · 当前权限：拥有者」</p>
```

**3. 跨页跳转（从别处跳进一个汇总页）**：同一个返回箭头，但只在"确实是从别处跳来"时出现，
目标放在地址里（`#/write-approvals?back=/roster/3`）。直接点侧栏进来时没有返回键。

规则：

- 返回键宽度固定 34px，与标题基线垂直居中；不要用 `<a class="btn">返回列表</a>` 这种右上角按钮
- 面包屑里只有**上一级**与**当前**两段，不出现三级
- 标题高度全站一致：`h1` 与返回键同一行，副标题另起一行

## 二、卡片

- 页面内容一律放进 `.card`，卡片之间用**统一间距 14px**（纵向、横向、以及两列版面与下一张整宽卡片之间都是 14）
- 一页里需要并排时用 `.cols-2 > .col`：**两列各自往下排，不做横向对齐**；两列最末一张卡片拉平到同一高度
- 卡片标题栏 `.card-head`：左侧是 `h2`（或状态数字），右侧依次是搜索框与按钮，全部 `min-height: 34px`
- 卡片内第一个字段不要有额外上边距；字段之间 12px

## 三、表格

- 一律 `<table class="tbl fixed">` + 列宽百分比写在 CSS 里（按表格 id 限定），不靠内容撑
- 第一列放可点击的对象名（`<a>` + `<b>`），下面可以跟一行 `.hint` 说明
- 数字列右对齐 + `.num`（等宽数字）；时间列 `.mono` + `PX.whenExact`
- 操作列固定在最右，`class="actions"`，单元格内右对齐
- **同一行两个按钮之间必须有 6px 间距**（`td.actions .btn + .btn { margin-left: 6px }`），
  按钮文字用动词短语：`编辑` / `移出` / `标为退出` / `恢复`，不用「打开」
- 空结果用 `emptyRow(列数, 文案)`，文案是「还没有…」或「没有匹配的…」
- 分页按钮放在表格下方的 `.row` 里，文案「再显示 N 条」
- **手机上（≤760px）表格横向滚动，不压成省略号**：`table.tbl` 给 `min-width: 640px`，
  由 `.tblwrap` 滑动；首列与 `.actions` 列各自 `position: sticky`（左 / 右），
  常用的按钮不用滑就够得着。桌面端不受这条影响

## 四、表单与控件

- 字段结构：`<div class="field"><label>…</label><input><p class="hint">…</p></div>`
- 原生日期/时间控件的占位符跟着浏览器语言走（`yyyy/mm/日 --:--`），所以**不用 `datetime-local`**：
  用两个文本框（`yyyy-mm-dd` / `HH:MM`，占位符自己写）+ 一个日历按钮调 `showPicker()`，
  另配一个「清除」按钮。日期接受 `2026/11/05`、`20261105`、`20261203T2359` 等写法，保存时改写成标准格式
- **手机上例外**：那两个文本框与日历按钮隐藏，换成整行可见的原生 `type="date"` / `type="time"`，
  点一下就是系统日历与时间轮，不用打字；选完照样写回文本框，保存逻辑只有一份
- 开关用 `.switch`：**不带文字**，只有胶囊本体，放在卡片标题栏右侧，`title` + `aria-label` 说明含义；
  设置项里要配一句话说明时，把那句话放进开关的 `<label>` 里（`.switch-text`），别让文字与轨道各站各的
- 开关的尺寸照 micula 的 `ToggleSwitch`：轨道 40×20、圆点直径 12、在中间那 20 上来回；
  值的变化 167ms 走 `cubic-bezier(0,0,0,1)`（Fluent 的减速曲线），悬停放大、按下压扁是 83ms，
  圆点绕自己的中心变，所以只缩放不移动
- 整块功能可关闭时：卡片加 `.is-off`，标题转灰、内容降到 45% 不透明度，开关保持全亮
- 下拉框自带描边箭头，不要再用浏览器默认外观

## 五、反馈

- **操作结果用 toast**（右上角，`PX.toast`）：一条短句，如「已保存」。toast 不进通知中心
- toast 可以带**一个小动作**：`PX.toast(文案, false, 毫秒, {icon, title, run})`，图标是
  关闭键左边的 18px 方块按钮，与关闭键同一行同高、**不改变这一条的高度**。
  用于"顺手接着做"的事（打开刚建的名单、打开报名页），不用于替代确认框
- **需要回看或需要人处理的事用通知中心**（右上角铃铛 + 红点）：写权限申请、审批结果、服务告警
- 通知分三级：`通知 / 重要 / 紧急`；紧急级未读会在下次打开面板时全屏弹出，
  只能点「已读」或「关闭」结束（ESC 等同关闭，点周围不消失）
- 表单级错误就地说明（`#err` 或字段下方的 `.hint`），不要只弹 toast
- **服务换了版本**：能安全刷新就自己刷新；这一页敲过字或有开着的弹窗时，在内容上方出
  一条 `.update-bar`（「服务已更新到 vX，刷新后使用新版本」+「刷新」），不要强行刷掉用户正在填的东西

## 六、措辞

- 书面语。不用「搞定」「弄一下」「顺手」，不用感叹号
- 页面说明不带句号；一句说清这一页做什么
- 按钮用动词：保存 / 创建 / 导入 / 移出 / 授予写入权限
- 状态词表：`进行中 / 未开始 / 已结束 / 已满 / 已禁用`、`在册 / 已退出`、`待确认`
- 时间一并写清时区语义：库里存 epoch，界面按本地时间显示到分钟，审计日志到秒

## 七、侧栏

- 第一节是"我自己的东西"：总览 / 运维助手 / 我的活动 / 预设管理 / 名单与报名
- 总览的四张牌都属于"我"：我的活动 / 我的名单 / 我的报名 / 待处理邀请；待审核申请与账号总数
  是整台机器的事，只对能评审、能看账号清单的人显示
- 中间是"管理"：用户管理 / 活动管理 / 活跃审批 / 外部资源（按角色显示）
- 底部单独：服务器管理 / 审计日志（站长）/ 界面设置 / 账户
- 只要能给人用的功能，就不能只放在站长页里：站长页放的是"整台机器"的东西
- 新功能先问一句"这是给谁用的"，再决定放哪一节
- 按角色隐藏项之后要收一遍分隔线：**没有可见项的节连同它后面的分隔线一起隐藏**，
  否则会出现空节与两条相邻的分隔线（看着像一条更粗的线）
- 整栏只占一个 Tab 位：上下方向键在可见项之间移动（展开的分组子项也在序列里），
  Home/End 到首尾；分组的展开/收起不额外占 Tab 位

## 八、抽屉（第二个从左边拉出来的东西）

- 面板里只有两种抽屉：**主侧栏**，以及运维助手的**会话列表**（`#asDrawer`）。
  两者同一套观感：贴左边、顶到标题栏下沿、宽 `min(86vw, 320px)`、右边一条分隔线，
  拉出/收回 220ms，`visibility` 跟着一起淡进淡出
- 遮罩（`#scrim`）是共用的：两处都收干净了才拿掉，不要各自开关一层
- 收起的方式都要有：点遮罩、按 Esc、点抽屉自己的关闭键，以及**换一页**（`onRoute` 里收）。
  抽屉不是路由的一部分，所以返回键回到别的页面时它必须跟着消失
- 抽屉里不做二次确认以外的事：选中即用（点一行就跳过去并收起），危险动作（删除）照旧弹确认

## 九b、滚动条

- 一寸地方都别浪费在系统默认滚动条上：它带着上下箭头和一块白底槽，在卡片中间或深色页面里
  都很扎眼
- 写法是两套并存：`:root { scrollbar-width: thin; scrollbar-color: var(--line) transparent; }`
  给现代 Chromium（这条路径不画箭头、槽透明），`::-webkit-scrollbar` 那套留给老一点的浏览器
- 一旦在别处再写 `scrollbar-width` / `scrollbar-color`，`:root` 这条就不再往下生效，
  所以只在这一处写

## 九、检查清单（新页面提交前）
1. 返回键是左侧圆角箭头吗？面包屑两段吗？
2. 卡片间距是不是都等于 14px？
3. 表格列宽写进 CSS 了吗？操作列两个按钮有间距吗？
4. 有没有用 `datetime-local`？
5. 开关带文字了吗？（卡片标题栏里不该带；设置项里那句话要放进 label）
6. 措辞是不是书面语？有没有多余的句号？
7. 空状态、加载中、出错三种情况都有话说吗？
8. 手机上（≤760px）还能用吗？表格能横向滑动、操作按钮够得着、日期能点出系统选择器、
   侧栏收起的分组不叠加？
9. 新加的 `data-*` 属性有没有和页面上已有的撞名？（页面用 `[data-rename]` 管活动改名，
   会话列表那份因此写成 `data-as-rename`）
