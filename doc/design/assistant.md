# 运维助手的设计

目标：把"查一下、改一下"变成一次对话，而不是让人在十几个页面之间找。约束先行——一个能替人操作的
助手，最容易出问题的地方不是模型不够聪明，而是**它绕过了平台已有的边界**。

## 三条硬约束

1. **权限不另立一套**：助手以当前登录账号的会话发出请求，打到本机自己的接口上。权限、CSRF、
   并发冲突、审计全部沿用现成那一套，一处都不用重写。
2. **模型在服务端调**：`base_url` / `model` / `api_key` 每人一份，密钥只写不读，浏览器永远拿不到。
3. **放行只走一个口**：每个动作先问 `policy.verdict()`，默认拒绝。

## 一次对话里到底传了什么

发给模型的只有三段：

1. **系统提示**：固定规则 + 「当前使用者：站长（owner）。」+ 平台提示词（运维自己写的那份 markdown）
2. **工具清单**：按这个账号的身份预先收窄（`policy.visible`）
3. **这段对话本身**（最近 20 条，每条截断到 4000 字符）

没有别的东西被塞进去。它不直接读数据库，也不持有任何服务凭据。唯一的例外是说明文档：
那是随应用装好的纯文本，由 `read_doc` 按需读进来，不进系统提示（否则每次对话都要付这份 token）。

工具的实现方式是：`assistant.PanelClient` 以 `127.0.0.1` + 调用者的 cookie + `X-Via: assistant`
去打平台自己的接口。这样"助手能看到什么"与"这个人手点能看到什么"必然一致——不是靠约定，
而是因为走的是同一条路。

「他是不是站长」由两件事回答：身份写在系统提示里，能做什么写在工具清单里。普通管理员的请求里
根本没有 `recent_audit`、`host_stats`，模型连它们存在都不知道，所以不会去撞权限墙——这比
"先给全部工具、再拒一次"少一轮无效调用，也少一次把平台能力暴露给不相干的人。

## 工具面：先读后写

目前只有十一个只读工具：活动列表与公示数据、名单与成员、报名与提交记录、人员检索、
说明文档（`list_docs` / `read_doc`）、审计日志（超级管理员及以上）、服务器状态（仅站长）。

**为什么让助手读文档**：把整份说明塞进系统提示会白白烧 token，而且改了文档还得改代码。
文档是纯文本、随部署一起到机器上，读一份只在被问到的时候花一次。文档里没有凭据，
所以对任何角色开放；读的时候有上限（一次 12000 字）、只认清单里出现过的路径（`../` 一律拒绝），
不存在"用提示词套路径"的口子。

**为什么模块文档也在清单里**：现场怎么操作是模块自己的事——同一套平台可以装完全不同玩法，
把某一种玩法写进平台文档会立刻过期。所以文档分两层：`doc/` 讲平台，`builtin/modules/<id>/doc.md`
（或实例装的 `modules/<id>/doc.md`）讲这个模块，助手看到的是同一份清单。

写入动作（改时间窗、加人、发通知、调奖品）还没有开放。原因不是技术：**放行判定要能回答
"谁在什么条件下可以让它改"**，而这个问题今天只有一个白名单的答案。所以先做只读，
把"动作"这一层的形状留出来：

```python
# policy.py
def verdict(account, action, params):
    """能不能让助手替这个人做这件事？返回 (allow, reason)。"""
```

调用点只有一个。将来接自动审计引擎（复核模型、频率限制、危险参数识别），换的只是这个函数的实现，
助手与业务接口都不用动。白名单之外还有一条硬线：**需要 sudo 的动作永远不在名单里**——
助手不能替人输密码，这条不随策略层变化。

## 提示词

系统提示由三段拼成：

- **固定规则**（写在代码里）：只回答平台范围内的事、只做账号有权做的事、改数据的动作不开放、
  简体中文书面语、不整段罗列个人信息
- **身份**：`当前使用者：<称呼>（<身份>；<登录名>）。` —— 写语气与称呼类提示词的前提
- **平台提示词**：`<数据目录>/assistant_prompt.md`，运维手工维护，按 mtime 缓存，上限 20 KB

平台提示词里可以写变量（`${user.role}`、`${time.date}`、`${tools}` 等），发出去之前按这次对话的
人替换；没定义的占位符原样留着，好让写错的地方露出来。变量清单见
[`../usage/assistant.md`](../usage/assistant.md#可以写的变量)。

## 对话存档

- 按会话存整段 JSON，体积记在 `size` 列上，按账号统计不必每次数消息
- 每个账号一份配额（默认 512 KB），满了拒绝保存并说明；站长可在用户管理里单独调
- 会话 id 进地址（`#/assistant/<id>`），开几个标签页就是几段互不打扰的对话
- 新会话请模型起一个不超过 12 个字的短名字；起不出来就用第一句话

## 审计

问一句**不写审计**：审计只记真正的操作，聊天本身会让它淹掉。助手真正改了东西时（将来接上写工具），
那次写入自己会记一条，detail 里带「经助手」——一眼分得清是人点的还是助手做的。

## 不做什么

- 不做"自动执行一串计划"：每次都要人问、人看结果
- 不把平台的密钥或令牌交给模型
- 不让助手替人做需要重新输密码的动作
- 不为了表现"智能"而绕过页面的二次确认：危险操作永远回原页面做
