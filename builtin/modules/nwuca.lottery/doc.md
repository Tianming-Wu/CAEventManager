# 奖票抽奖 · 现场说明

模块 `nwuca.lottery`。它往活动后台里加五个页面：操作台、名单、奖票、抽奖、奖票设置。
平台的公共页面（公示页、大屏、签到、活动设置、日志）见 `doc/usage/event.md`。

## 现场用哪台设备

| 干什么 | 建议设备 | 为什么 |
| --- | --- | --- |
| 操作台（签到、任务、搜索找人） | **电脑或平板**，带键盘 | 搜索框是给"关掉中文输入法、直接打拼音首字母或全拼"这种输入方式设计的；手机上打字速度达不到现场节奏 |
| 大屏、签到二维码 | 投影 + 手机扫码 | — |
| 名单浏览、导出 | 手机也能用 | 表格会横向滚动 |
| 抽奖 | 电脑 | 动画与节奏要人工控制，且要给大屏看 |

## 操作台

现场的主页面，一屏看全所有人。

- **搜索**：一个框同时匹配姓名、全拼、首字母与学号片段。设计前提是**键盘直打**：
  关掉中文输入法，打 `gaogao` 或 `gg` 或 `2024001` 都能找到人。用手机软键盘达不到这个速度，
  所以现场请用电脑
- **完成任务**：参与者依次完成 签到 → 任务一 → 任务二。前一环没完成时后面的标记会被拒绝，
  并指出缺哪一步
- **解锁修改**：现场总有例外（设备故障、临时改流程）。打开之后可以越序标记，这一条会在操作日志里
  带上「越序：未完成 ……」的说明——数据留下的是"当时确实这样做了"，而不是把它抹平。
  30 秒无操作自动上锁
- **奖票**：按奖票池规则发放，每张票按顺序发号，与池子大小解耦

## 奖票池

| 模式 | 取值 | 什么时候用 |
| --- | --- | --- |
| 自动 | 到场人数 × 3 + 常数（默认 20） | 跟着真实到场人数走，保底票永远发得出 |
| 固定 | 指定张数 | 印了确定数量实物票时 |
| 表达式 | 例如 `signed_in * 3 + 20` | 需要按现场形状伸缩时 |

表达式由一个小型求值器执行，只允许数字、上下文名字、四则运算与 `min max round abs int`，
没有 `eval`。可用名字：`signed_in`、`present`、`participants`、`staff_present`、`tasks_done`、
`guaranteed`、`bonus_constant`、`pool_size`。池子可以中途上调，也可以下调到不低于已发张数。

## 抽奖

- 每个奖品各有一档**节奏**：逐个（点一次抽出一个人，配合大屏动画）或一次抽完（点一次抽出剩余
  名额，大屏只播一次动画再列出得主）。节奏随奖品保存，换台电脑打开还是这一档
- 两个独立的去重开关，在「奖票设置」里：**同一个奖不重复同一个人**；**一个人不能同时拿两个奖**
- 按人抽取的奖（例如特等奖，所有到场者等概率）只受第一条约束：它不抽票，与按票的奖互不排斥
- 作废一条抽奖记录，这个人即恢复资格
- 材料不够时（可抽的票少于剩余名额）会抽出能抽的部分，并说明原因

## 名单页

- 支持 CSV / TSV 导入，有表头自动识别，按学号增量更新，重复导入不留重复记录
- 区分参加人员 / 工作人员 / 志愿者：后两者只记到场，仍参与特等奖
- 活动结束后导出 ZIP：`01-汇总`、`02-名单`、`03-奖票明细`、`04-抽奖记录`、`05-中奖汇总`
  五张 CSV 与 `06-操作日志.log`

## 预设

随模块发布的预设是 `salon.json`（小型沙龙：一次到场、两个任务、保底票）。它只设模块声明过的参数，
写别的键会被拒绝。要按自己的流程开活动，在现场调好之后用活动卡片菜单「保存为预设」。
