# 活动页面与现场

活动的内容是**模块**：装上并启用某个模块，才有它的页面与设置。平台自己只提供每个活动都有的那几页
（公示页、大屏、签到、活动设置、日志），模块往活动后台里加自己的页面。

```
/<前缀>/<token>/           公示页（只读，不需要登录）
/<前缀>/<token>/screen     大屏投影
/<前缀>/<token>/checkin    自助签到（必须扫大屏二维码进入）
/<前缀>/<token>/admin      活动后台（用面板账号登录）
/<前缀>/<token>/login      跳到面板登录，登录后回到这个后台
/<s 短码>                  限时短码跳转，由后台生成
```

`<token>` 是 32 位访问凭据，本身就是地址中的一段；数字 `seq` 只用于存储，不出现在地址里。

活动后台没有自己的账号体系：它用面板账号登录，沿用同一个会话 cookie，所以同一个浏览器里不用
输第二次密码。能否进入取决于这个账号是不是本活动的成员（负责人或成员），邀请与确认见
[`panel.md`](panel.md#活动)。

## 平台提供的页面

### 公示页

只读，不需要登录，任何人都能打开。显示签到人数、任务完成数、已发奖票与中奖名单。
用于把链接发到群里，或者放在教室门口的屏幕上。

### 大屏

投影用。签到阶段显示签到二维码（按 10 秒窗口切片，过期就换一张）；抽奖阶段换成活动地址与
常驻的中奖名单。抽奖动画播完之前不会因为服务更新而刷新——现场不会看到一半的动画被切断。

大屏是一份可替换的插接件：活动不写就用自带的展示页；站长与超级管理员可以在
「外部资源 › 展示屏幕」导入一份自己的（zip，包内需要 `screen.html`，只接受
`.css .js .svg .png .jpg .jpeg .webp`，包不超过 2 MB、解开后总量不超过 8 MB）。

### 签到

必须扫大屏上的二维码进入：二维码里的 token 有时效，扫码通过后这台手机得到一个签名 cookie，
再填学号与姓名，两项都与名单匹配才算签到成功。这样可以避免把签到页的链接转发出去乱签。
站长可以在活动设置里关掉自助签到。

### 活动设置

平台画的，管的是与玩法无关的东西：

- **成员**：按登录名或称呼搜人、发出邀请；对方在自己的面板「我的活动」里确认一次才算加入。
  移出不删记录：席位变成「已移出」并留下时间，随时可以重新邀请。负责人不能把自己移出，
  也不能移出活动里唯一的负责人
- **活动本身**：名称、访问地址（重新生成后旧链接立即失效，需要重新输密码）、存档
- **展示屏幕**：这个活动用哪一份大屏

### 日志

活动自己的操作日志：谁在什么时候改了什么。与面板的审计日志分开——这一页是给现场复盘用的。

### 归档

活动不会消失：存档之后它从列表退到「活动管理 › 归档的活动」，标题、负责人、归档时间都留着，
数据库文件不动。存档是带 sudo 的操作，所以那边不再给"取消归档"按钮。

## 模块自己的页面

模块的页面、现场怎么操作、用哪台设备，写在模块自己的说明里：

- 内置的「奖票抽奖」模块：`builtin/modules/nwuca.lottery/doc.md`
  （活动后台里的操作台、名单、奖票、抽奖、奖票设置都由它提供）
- 实例自己装的模块：`modules/<模块 id>/doc.md`

这些说明与 `doc/` 一起随应用装到机器上，运维助手也能读（`list_docs` / `read_doc`），
所以在现场问"操作台的搜索怎么用"时，它查到的是模块自己写的那一段，而不是平台文档里的猜测。
